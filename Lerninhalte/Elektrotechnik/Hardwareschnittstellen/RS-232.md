**[[RS-232]]** ist eine [[Hardwareschnittstellen|Hardwareschnittstelle]], die zur Übertragung von Daten [[UART]] verwendet
# Eigenschaften

| **Eigenschaftsbezeichnung**                    | Eigenschaft                                                                                                             |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **OSI‑Schicht** (siehe [[OSI-Referenzmodell]]) | Physikalische Schicht (Electrical/PHY), nicht das Protokoll                                                             |
| **Signalführung**                              | Single‑Ended (unbalanced)<br>-> Asymmetrisch<br>-> einadrige Signalführung                                              |
| **Signalreferenz**                             | $U_{\mathrm{GND}}$ (gegen GND)                                                                                          |
| **mögliche Topologien**                        | Typisch Punkt‑zu‑Punkt, Bus-/Multipoint‑Topologien sind bei RS‑232 **nicht vorgesehen** und in der Praxis störanfällig. |
| **Duplex**                                     | Vollduplex                                                                                                              |
| **Richtungssteuerung**                         | Normalerweise keine (weil Vollduplex). Keine Driver‑Enable‑Umschaltung wie bei RS‑485.                                  |
| **Teilnehmerfähigkeit**                        | Nicht multipoint‑fähig (genormt für 1 Sender ↔ 1 Empfänger).                                                            |
| **Terminierung**                               | Keine Terminierung                                                                                                      |
| **Biasing / Fail-safe**                        | Untypisch                                                                                                               |
| **Typische Protokolle „darauf“**               | [[UART]], NMEA‑0183 (GPS), proprietäre Protokolle; teils auch Modbus RTU                                                |

# Pinout (DB-9 / DE-9)

| Pin | Signal | Richtung | Bedeutung |
|---|---|---|---|
| 1 | DCD | IN | Data Carrier Detect – Trägersignal erkannt |
| 2 | RxD | IN | Receive Data – Empfangsdaten |
| 3 | TxD | OUT | Transmit Data – Sendedaten |
| 4 | DTR | OUT | Data Terminal Ready – Terminal bereit |
| 5 | GND | – | Signalmasse |
| 6 | DSR | IN | Data Set Ready – Gegenstelle bereit |
| 7 | RTS | OUT | Request To Send – Sendeanfrage |
| 8 | CTS | IN | Clear To Send – Sendeerlaubnis |
| 9 | RI | IN | Ring Indicator – ankommender Anruf |

## Steckertypen
- **DB-25 (D-Sub 25)**: Ursprünglicher Stecker nach RS-232-Standard, 25 Pins
- **DE-9 (DB-9)**: Kompakte Variante mit 9 Pins – heute am weitesten verbreitet
- **RJ-45**: Manchmal für serielle Verbindungen genutzt (kein RS-232-Standard)

## Minimale Verdrahtung (3-Draht)
Für einfache Kommunikation ohne Flusskontrolle:
- Pin 2 (RxD) ↔ Pin 3 (TxD) der Gegenstelle
- Pin 3 (TxD) ↔ Pin 2 (RxD) der Gegenstelle
- Pin 5 (GND) ↔ Pin 5 (GND)

## Volle Verdrahtung (9-Draht)
Alle 9 Signale des DE-9-Steckers verbunden, inkl. Hardware-Flusskontrolle (RTS/CTS, DTR/DSR).

# Flusskontrolle mit RTS/CTS
Die Hardware-Flusskontrolle verhindert, dass Daten verloren gehen, wenn der Empfänger nicht bereit ist.

## Datenempfangsbereitschaft
- **DTR (Data Terminal Ready)**: Sender signalisiert, dass er Daten empfangen kann
- **DSR (Data Set Ready)**: Gegenstelle signalisiert, dass sie bereit ist

## Datensendeanfrage
- **RTS (Request To Send)**: Sender möchte Daten senden
- **CTS (Clear To Send)**: Gegenstelle erlaubt das Senden

## Überbrückung
Ohne Flusskontrolle können RTS/CTS und DTR/DSR überkreuz überbrückt werden (Loopback), damit die Kommunikation trotzdem funktioniert.

# Ablauf
## Parallel zu Seriell
-> Daten werden vom Bus empfangen
## Datenergänzung
[[UART]] ergänzt Daten (je nach Konfiguration) um:
	- Startbit
	- Paritätsbit
	- Stopbit
## Serielle Übertragung
- Das komplette Datenpaket wird nun seriell übertragen
- Der Empfänger nimmt die Daten in seiner konfigurierten Baudrate auf
## Datenwandlung
Der Empfänger löscht nun die drei Komponenten:
- Startbit
- Paritätsbit
- Stopbit
## Seriell zu Parallel
Das Datenpaket wird anschließend auf dem Datenbus bereitgestellt
# Signalpegel
| Signal | Logisch HIGH | Logisch LOW |
|---|---|---|
| **RS-232** | $-3\,\mathrm{V}$ bis $-15\,\mathrm{V}$ | $+3\,\mathrm{V}$ bis $+15\,\mathrm{V}$ |
| **TTL** | $\geq 2{,}0\,\mathrm{V}$ | $\leq 0{,}8\,\mathrm{V}$ |

RS-232 ist **invertiert** gegenüber TTL: Ein negativer Pegel bedeutet HIGH, ein positiver Pegel bedeutet LOW.
# RS-232 vs TTL vs V.24

| Eigenschaft | [[RS-232]] | TTL | V.24 |
|---|---|---|---|
| **Was ist es?** | Elektrische Schnittstellennorm (TIA/EIA-232) | Logikpegel-Standard | ITU-T-Empfehlung (protokollarisch/funktional) |
| **Logik HIGH** | $-3\,\mathrm{V}$ bis $-15\,\mathrm{V}$ | $\geq 2\,\mathrm{V}$ (bei $5\,\mathrm{V}$-Versorgung) | – |
| **Logik LOW** | $+3\,\mathrm{V}$ bis $+15\,\mathrm{V}$ | $\leq 0{,}8\,\mathrm{V}$ | – |
| **Invertiert?** | Ja (negativ = HIGH, positiv = LOW) | Nein | – |
| **Bereich** | Nur elektrisch | Nur elektrisch | Pinbelegung + Signalnamen |
| **Zusammenhang** | RS-232 definiert die **Spannungen** | TTL = interne MCU-Logikpegel | V.24 definiert die **Funktion/Pins** – RS-232 ist die elektrische Umsetzung |

> [!tldr] Merksatz
> **V.24** = welche Pins/Signale es gibt (funktional), **RS-232** = welche Spannungen darauf laufen (elektrisch), **TTL** = MCU-interne Logikpegel ($0$/$5\,\mathrm{V}$).
